# Технические решения и открытые вопросы

Здесь фиксируем решения, которые влияют на несколько частей проекта, и вопросы, где выбор ещё не сделан. Когда вопрос закрывается, запишите принятое решение, причину и ссылку на задачу или PR, если они есть. Поведение API описано в [функциональности](features.md), команды проверки — в [руководстве по разработке](development.md).

## Действующие решения

| Решение | Причина или следствие |
| --- | --- |
| Go для сервиса и инструментов проекта, Make для команд разработки | `make check` одинаково запускается локально и в CI. Python исключён из кода, скриптов и зависимостей. [Makefile](../Makefile) · [CI](../.github/workflows/ci.yml) |
| PostgreSQL через pgx, изменения схемы через SQL-миграции Goose | Запросы и границы транзакций видны в репозиториях. В Docker Compose миграции применяются перед запуском API. [Репозитории](../internal/repository) · [Миграции](../migrations) · [Dockerfile](../Dockerfile) |
| Остаток мест меняется в той же транзакции, что и состояние брони | Создание блокирует строку поездки перед проверкой остатка. Ручная отмена и фоновая очистка возвращают места в транзакции, которая переводит бронь в `cancelled` при ручной отмене или в `expired` при фоновой очистке. [Репозиторий бронирований](../internal/repository/booking_repo.go) |
| Фоновая очистка работает в процессе API | Воркер стартует вместе с HTTP-сервером и принимает тот же контекст остановки. По умолчанию он раз в минуту проверяет брони в `pending` старше 15 минут. [Точка входа](../cmd/api/main.go) · [Воркер](../internal/worker/booking_worker.go) |
| Stripe Checkout в песочнице, суммы в USD | До появления валюты в модели поездки цена интерпретируется в USD для тестовой оплаты. Подписанный вебхук подтверждает действующую бронь. При поздней оплате запрашивается возврат, а пользовательская отмена оплаченной брони закрыта. [Жизненный цикл](features.md#жизненный-цикл-брони) |
| Завершение поездки хранится в `trips.completed_at` | Водитель-владелец отмечает завершение после времени отправления. Список броней выводит `completed` для подтверждённых броней этой поездки. Исторические `cancelled` сохраняются: прежняя схема не фиксировала причину закрытия. [Жизненный цикл](features.md#жизненный-цикл-брони) |

## Открытые вопросы

| Вопрос | Что нужно решить |
| --- | --- |
| Как проверять транзакции бронирования в CI? | Тесты обработчиков и воркера используют моки, а `make smoke` проверяет только публичное чтение. Нужно выбрать способ запуска изолированного PostgreSQL и проверять конкурентное бронирование последнего места и одновременную ручную отмену с очисткой. [Разработка и проверка](development.md) |
| Как завершать HTTP-запросы при остановке процесса? | Сигнал отменяет контекст воркера, HTTP-сервер запускается через `http.ListenAndServe`. Нужно определить, сколько времени давать активным запросам и воркеру до закрытия пула PostgreSQL. [Точка входа](../cmd/api/main.go) |
