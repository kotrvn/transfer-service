# Функциональность Transfer Service

Водитель публикует поездку, пассажир ищет её по городам и бронирует места. Клиент получает JWT при входе и передаёт его в заголовке `Authorization: Bearer <token>` для защищённых маршрутов.

## Маршруты

| Метод и путь | Доступ | Результат |
| --- | --- | --- |
| `GET /health` | Публичный | `200` и статус HTTP-сервера |
| `POST /api/v1/users/` | Публичный | `201` и профиль новой учётной записи с ролью `driver` или `passenger`. Хеш пароля исключён из ответа |
| `POST /api/v1/users/login` | Публичный | `200` и объект с полем `token`. JWT действителен 24 часа |
| `GET /api/v1/trips` | Публичный | `200` и список поездок. Опциональные параметры `from` и `to` фильтруют по подстроке без учёта регистра |
| `POST /api/v1/trips` | Водитель | `201` и новая поездка. Идентификатор водителя берётся из JWT, все места изначально свободны |
| `POST /api/v1/bookings` | Пассажир | `201` и бронь в статусе `pending` |
| `GET /api/v1/bookings/my` | JWT | `200` и все брони пользователя из JWT, включая отменённые |
| `DELETE /api/v1/bookings/{id}` | JWT, владелец брони | `204`, бронь получает статус `cancelled`, места возвращаются в поездку |

Пустые списки возвращаются как `[]`. Проверка JWT выполняется в middleware. Роли водителя и пассажира для создания поездок и броней проверяют обработчики. При отмене принадлежность брони проверяет репозиторий.

Маршруты и middleware зарегистрированы в [cmd/api/main.go](../cmd/api/main.go). Тела запросов и правила валидации описаны в [internal/models](../internal/models). Сгенерированная спецификация доступна в [swagger.yaml](api/swagger.yaml).

## Жизненный цикл брони

1. Пассажир отправляет `trip_id` и положительное число мест в `seats`. Репозиторий блокирует строку поездки через `FOR UPDATE`, проверяет доступность мест и в одной транзакции уменьшает остаток и создаёт бронь. Отсутствующая поездка даёт `404`, нехватка мест даёт `400`.
2. При ручной отмене репозиторий блокирует бронь владельца и в одной транзакции обновляет статус и возвращает места. Повторная отмена возвращает `400`.
3. Воркер запускает проверку раз в минуту. Брони в `pending` старше 15 минут переходят в `cancelled` с возвратом мест в той же транзакции. Время считается по `bookings.created_at` в PostgreSQL.

Статус `confirmed` указан как значение по умолчанию в SQL-схеме. Обработчик создания явно передаёт `pending`, а отдельного HTTP-маршрута подтверждения в текущем API нет.

При создании и чтении брони фактический `created_at` из БД пока не загружается. В JSON возвращается нулевое значение времени Go, а воркер использует реальное значение из PostgreSQL.

Запросы и границы транзакций находятся в [booking_repo.go](../internal/repository/booking_repo.go), цикл очистки — в [booking_worker.go](../internal/worker/booking_worker.go).
