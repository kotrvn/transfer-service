# Transfer Service

HTTP API для поиска поездок и бронирования мест. Для кода и инструментов проекта используйте Go и существующие команды Make. Python в проекте не используется, включая скрипты и зависимости.

## С чего начать

- [Функциональность](docs/features.md) описывает маршруты, роли и жизненный цикл брони.
- [Разработка и проверка](docs/development.md) связывает типы изменений с файлами и проверками.
- [Технические решения и открытые вопросы](docs/decisions.md) фиксирует действующие решения и вопросы, которые ещё предстоит согласовать.
- [Роадмап](docs/roadmap.md) показывает приоритеты и критерии готовности следующих этапов.
- [План фронтенда](docs/frontend-plan.md) описывает архитектуру и первый сценарий входа. Визуальные правила и токены находятся в [DESIGN.MD](DESIGN.MD).
- [README](README.md) содержит команды запуска API и CI-проверок.

## Перед завершением задачи

1. Сверьте затронутое поведение с маршрутом, реализацией и ближайшими тестами. Если текущее поведение отличается от документации, укажите расхождение и исправьте описание в рамках задачи.
2. При изменении HTTP-контракта обновите Swagger-аннотации, перегенерируйте спецификацию в [docs/api/](docs/api/) и обновите описание затронутой фичи. Изменения схемы оформляйте новой SQL-миграцией Goose.
3. Запустите `make check`. Для изменений SQL и миграций проверьте затронутый сценарий на локальном PostgreSQL. В итоговом отчёте укажите, какие проверки удалось выполнить.
4. Если работа разбита на шаги плана, после проверки каждого шага делайте отдельный коммит перед переходом к следующему.
