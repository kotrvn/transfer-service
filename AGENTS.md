# Transfer Service

HTTP API для поиска поездок и бронирования мест. Для кода и инструментов проекта используйте Go и существующие команды Make. Python в проекте не используется, включая скрипты и зависимости.

- [Разработка и проверка](docs/development.md) связывает типы изменений с файлами и проверками.
- [Технические решения и открытые вопросы](docs/decisions.md) фиксирует действующие решения и вопросы, которые ещё предстоит согласовать.

## Перед завершением задачи

1. Сверьте затронутое поведение с маршрутом, реализацией и ближайшими тестами. Если текущее поведение отличается от документации, укажите расхождение и исправьте описание в рамках задачи.
2. При изменении HTTP-контракта обновите Swagger-аннотации, перегенерируйте спецификацию в [docs/api/](docs/api/) и обновите описание затронутой фичи. Изменения схемы оформляйте новой SQL-миграцией Goose.
3. Запустите `make check`. Для изменений SQL и миграций проверьте затронутый сценарий на локальном PostgreSQL. В итоговом отчёте укажите, какие проверки удалось выполнить.
4. Если работа разбита на шаги плана, после проверки каждого шага делайте отдельный коммит перед переходом к следующему.

## Сообщения коммитов агентов

Когда агент создаёт коммит, заголовок должен начинаться с префикса области изменения.

- `[Front]` — интерфейс и код в `frontend/`.
- `[Back]` — Go API, логика сервиса, схема PostgreSQL и Swagger.
- `[Infra]` — CI, Docker, деплой, инструменты сборки и правила репозитория.

Если коммит затрагивает несколько областей, укажите все подходящие префиксы в порядке `[Front] [Back] [Infra]`. Отделяйте префиксы и заголовок пробелами. Например, `[Front] [Back] Add trip completion`.

## Защита репозитория и пуш

- Удаление репозитория запрещено. При изменениях сохраняйте файлы, необходимые для сборки, запуска, CI и миграций. Если задаче требуется перенос критичного файла, проверьте замену и всех её потребителей до коммита.
- Перед каждым пушем проверьте отправляемый коммит на чистом рабочем дереве. Обязательны `make check`, `npm run lint`, `npm run typecheck`, `npm run build` из `frontend/` и `make smoke` на локальном API. Затронутый пользовательский сценарий проверьте вручную или браузерной автоматизацией на текущей сборке. Если обязательная проверка не проходит, исправьте причину до пуша.
- Используйте [pre-push hook](.githooks/pre-push) из репозитория. Настройка нового клона описана в [руководстве по разработке](docs/development.md#проверка-перед-пушем). Пуш выполняется с включённым hook.
